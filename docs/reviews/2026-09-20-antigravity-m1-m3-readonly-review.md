### M2 additional Critical findings

1. **Telegram bot bypasses the legacy freeze when configured.** Backend startup imports `server/bot.js` (`server/index.js:2606-2611`); with a valid bot token it polls and writes through legacy repository functions, including case upsert/status and assessment/MPZIS/PPD paths (`server/bot.js:6-17,37-40,160-205,289-381,401-487`). Those paths do not traverse the HTTP legacy guard. Guard or disable all bot writes at cutover **before** download/file/DB side effects, preserving any authorized read-only bot behavior; test token-enabled cutover with zero side effects. Whether the bot is active on production was not checked here.
2. **Reconciliation can enter/exit P0 without its required evidence gate.** `beginLegacyReconciliation` can change an existing P0 case into `legacy_reconciliation` because it only rejects read-only cases (`server/penyaluran-p0/legacy-reconciliation.js:497-526`). `completeLegacyReconciliation` accepts a case without proving it is in reconciliation, without expected status/version, and unconditionally changes mode to `p0` (`:552-593`). The committed lifecycle test treats a bare mode switch as success (`server/penyaluran-p0-legacy.test.js:501-517`). The specification requires rebuilding authoritative artifacts, imported-value hashes, actor gates, and the unchanged-status gate before atomic completion (`docs/superpowers/specs/2026-09-13-mustahik-p0-digitalization-design.md:545`). Make start/complete state-checked and idempotent, and add adversarial evidence-chain tests. This is the M2 owner of the reconciliation concern also observed by the M3 reviewer.

### M2 additional Important findings

1. **Idempotency key is optional.** Archive/restore only reserve a key when truthy (`server/penyaluran-p0/legacy-reconciliation.js:268-286,386-404`), although the API contract requires one with expected status/version for both retention operations (`docs/superpowers/specs/2026-09-13-mustahik-p0-digitalization-design.md:397-399`). Reject missing/invalid keys before mutation at service and HTTP boundaries. The earlier finding about hashing omitted state controls and restore's missing status check remains separate.
2. **Archived legacy cases can still be mutated before cutover.** Archive sets `archived_at`, but `assertLegacyWriteAllowed` does not reject it (`legacy-reconciliation.js:101-143,312-318`); the HTTP guard fetches `archived_at` without enforcing it (`:167-177`). Require restore before all legacy writes, with route and direct-service tests.
3. **Cutover configuration can fail open.** Missing or invalid `PENYALURAN_P0_CUTOVER_AT` makes `isP0CutoverActive` return false (`legacy-reconciliation.js:24-29`); enabling the P0 flag alone does not freeze guarded legacy routes. Add startup/release validation and an explicit fail-closed policy for contradictory P0-enabled/cutover configuration.
4. **Retention endpoint path differs from the approved API contract.** The specification names `/api/admin/penyaluran/mustahik/:id/archive|restore` (`...digitalization-design.md:397`), but committed routes are `/api/mustahik/:id/archive|restore` (`server/index.js:2373-2409`). Reconcile route and client contract deliberately, preserving authorization and compatibility as needed; do not merely change the report text.
