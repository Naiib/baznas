## M3 — case read model: NO-GO

1. **Critical — assignmentless cases remain readable across scope.** `assertCaseScope` denies only when assignment rows exist **and** the actor is not among them (`server/penyaluran-p0/case-read-model.js:272-301`). With zero active assignments, any permitted operational role can read the full workspace; the strict artifact-file authorization requires an actual assignment (`server/penyaluran-p0/artifact-files.js:221-231`). Deny by default for operational workspace reads, including zero/ended-assignment cases; preserve admin cross-case audit. Test over real authenticated HTTP paths and ensure assignment role is honored. If assignmentless triage is needed, expose a separate minimal queue contract rather than full case artifacts.
2. **Important regression — completion incorrectly waits for receipt PDF readiness.** `computeProvenCompletion` requires `receipt_status='ready'` (`case-read-model.js:244-253`), but the completion transaction sets PPD `completed` with receipt `pending` before asynchronous generation (`server/penyaluran-p0/completion-service.js:219-221`). The specification says a failed PDF job does **not** undo the completed case (`...digitalization-design.md:348-349`). Keep completion state separate from receipt pending/failed/ready and test both pending and failed outcomes; the new test only covers ready (`server/m1-m3-remediation.test.js:422-440`).
3. **Important — non-P0 cases can still appear digitally completed.** The same helper returns true for `legacy` and `legacy_reconciliation` from status/PPD status alone (`case-read-model.js:244-247`), and its test endorses a legacy completed status as proof (`m1-m3-remediation.test.js:438-440`). Show historical completion status separately from P0 digital proof; do not award P0 completion or receipt capability before audited reconciliation.
4. **Important — “proven” evidence is mostly field-shape checking.** The helper checks a truthy proof-file ID, verification label, and confirmation timestamp, not proof-file scope/hash, amounts, actor separation, immutable snapshot chain, or persisted completion event (`case-read-model.js:248-253`). The new test passes hand-built objects (`m1-m3-remediation.test.js:424-436`). Prove the upstream completion service guarantees these invariants with adversarial persisted-record tests, or derive a narrower truthful projection; do not claim cryptographic/full-chain proof from this helper alone.
5. **Important — remaining read-model gaps.** Absent amounts/descriptions still become `0`/`''` (`case-read-model.js:55,439-468`). Payment/confirmation and receipt timeline events lack actor snapshots, and the new tests do not establish event coverage/order (`:585-625`). Schema-not-ready handling is improved, but lacks an actual missing-relation HTTP test; admin reads bypass the assignment-table readiness check (`:67-90,272-275`). Finish null-preservation, chronology, and real schema-failure tests before M3 acceptance.
